# Интеграция «ЕГДС» для Home Assistant

![Баннер](docs/banner.png)

Управление шлагбаумами (КПУ) и просмотр живого видео с камер сервиса
**ЕГДС** (`client.egdsk.ru`) из Home Assistant.

Интеграция построена на протоколе, восстановленном обратной разработкой
официального приложения **ЕГДС 3.3.25** (Android, пакет
`ru.egds.EgdsMobile`, XAPK от APKPure). Приложение — .NET MAUI; управляемые
сборки извлечены из `libassembly-store.so` (формат XABA/XALZ), логика
восстановлена по IL-коду и строкам `EgdsMaui.dll`, ключевые запросы
проверены живыми вызовами сервера.

---

## Протокол (кратко)

| Что | Как |
|---|---|
| Хост API | `https://client.egdsk.ru` |
| Аутентификация | OAuth2, `POST /oauth/token`, `Content-Type: application/x-www-form-urlencoded` |
| Клиент | `Authorization: Basic base64("AndroidApp_1.3:Secret#1")` |
| Выслать SMS | `grant_type=sms&phone_number={телефон}` |
| Вход | `grant_type=password&username={телефон}&password={код из SMS}` |
| Ответ входа | JSON: `access_token`, `refresh_token`, `token_expires`, `base_token`, `start_demo`, `course_url` |
| Обновление токена | `grant_type=refresh_token&refresh_token={rt}` |
| Список КПУ | `GET /mobile1/barrier/addresses`, `Authorization: Bearer {access_token}` |
| Открыть | `{endpoint}/mobile1/barrier/open/{id}`, Bearer-токен |
| Видео | `https://{host}:{port}/rsapi/snapshot?id={Guid}` — кадр; `.../rsapi/mjpeg?id={Guid}&framerate=..&viewSize=..` — поток; авторизация `Basic {Login}:{Password}` камеры |

Структура адресов: `Address{Id, Name, Barriers:[EBarrier{Id, Number,
GroupName, Name, Cameras:[Camera{Id, Name, Host, Port, Guid, Login,
Password}]}]}` — интеграция разбирает ответ без учёта регистра ключей
и поддерживает обёртки `{data: [...]}`.

Демо-режим приложения использует телефон `0001234567`.

## Возможности

| Сущность | Описание |
|---|---|
| `button.*_otkryt` | Кнопка «Открыть» для каждого доступного вам КПУ |
| `cover.*_shlagbaum` | Шлагбаум как cover: команда открытия, «предполагаемое» состояние (открывается → открыто → закрыто) |
| `camera.*_kamera` | Живая камера КПУ: MJPEG-поток (`rsapi/mjpeg`) и JPEG-кадры (`rsapi/snapshot`), Basic-авторизация камеры |

- Сервис `egds.open_barrier` — открыть шлагбаум из автоматизаций.
- Токены хранятся в записи конфигурации и обновляются проактивно
  (за 2 минуты до истечения): рестарты HA и refresh-гранты не требуют
  повторного SMS-входа.
- Повторная авторизация без удаления интеграции: из меню настроек или
  автоматически, когда refresh-токен окончательно истёк (reauth-flow,
  новый код высылается сразу).
- Защита от повторных команд (20 секунд, настраивается).
- Опции: интервал опроса, тайминги состояния, кулдаун, framerate/viewSize
  видеопотока.

## Повторная авторизация и сессии (интеграция + приложение)

OAuth2-токены ЕГДС хранятся в записи конфигурации: рестарт Home Assistant
и обновления `access_token` не требуют повторного входа по SMS. Свежие
токены (включая ротированный `refresh_token`) сразу сохраняются обратно в
запись, поэтому цепочка обновлений не рвётся.

Повторная авторизация нужна только если refresh-токен окончательно истёк
или сессию перехватил свежий вход (например, вы заново вошли в приложение
на телефоне). Тогда HA покажет на карточке интеграции «Требуется повторная
авторизация»: код высылается сразу, остаётся ввести его. Запустить её
вручную можно в любой момент: **Настройки → Устройства и службы → ЕГДС →
⚙ → «Повторная авторизация (новый код)»** — удалять и заново добавлять
интеграцию не нужно.

Учтите: свежий вход (`grant_type=password` по коду) может завершить
сессию приложения на телефоне — это поведение сервера ЕГДС. При этом
пока Home Assistant просто опрашивает сервер по сохранённым токенам,
приложение работает параллельно без ограничений; если сервер HA
недоступен, приложение остаётся полностью рабочим резервным каналом.

## Установка

### Через HACS (рекомендуется)

[![Открыть в HACS](https://img.shields.io/badge/HACS-Установить-0366d6?logo=homeassistant&logoColor=white)](https://my.home-assistant.io/redirect/hacs_repository/?owner=NoIDXMV6&repository=egds-ha&category=integration)

1. Установите [HACS](https://hacs.xyz/docs/use/download/download/), если ещё не установлен.
2. **HACS → ⋮ → Добавить свой репозиторий (Custom repository)**.
3. Вставьте адрес: `https://github.com/NoIDXMV6/egds-ha`, категория — **Интеграция**.
4. Установите «ЕГДС (шлагбаумы)» и перезапустите Home Assistant.
5. **Настройки → Устройства и службы → Добавить интеграцию → ЕГДС**.

### Вручную

1. Скопируйте папку `custom_components/egds` в `config/custom_components/`
   вашего Home Assistant (через Samba/Studio Code Server или git).
2. Перезапустите Home Assistant.
3. **Настройки → Устройства и службы → Добавить интеграцию → ЕГДС**.
4. Введите телефон (как в приложении) и запросите код.
   - Код придёт способом, подключённым для аккаунта: SMS или звонок
     (код — последние 4 цифры номера звонившего) доступны всем при входе;
     Telegram и email — если подключены.
   - Если сервер ответил «нет доступных способов доставки» — подключите
     каналы в приложении ЕГДС без сайта: «Настройки уведомлений» →
     подтвердите email («Запросить подтверждение EMail») и/или
     Telegram (подтвердите телефон в боте t.me/egdsk_bot).
   - Код не пришёл — отметьте «Выслать код повторно» и повторите.
     Личный кабинет на сайте для этого не нужен — он доступен только
     контактным лицам по договору.
5. Введите полученный код → готово: на каждый КПУ добавятся устройство,
   кнопка, шлагбаум и камера.

Требования: Home Assistant 2024.x–2025.x. ffmpeg не нужен — камера
отдаёт MJPEG напрямую.

## Использование в автоматизациях

```yaml
automation:
  - alias: Открыть шлагбаум по прибытии
    triggers:
      - trigger: device_tracker
        entity_id: device_tracker.my_phone
        to: "home"
    actions:
      - action: button.press
        target:
          entity_id: button.ul_tveretskaya_otkryt

# или через фирменный сервис:
      - action: egds.open_barrier
        target:
          entity_id: cover.ul_tveretskaya_shlagbaum
```

## Вывод видео на панель (Lovelace)

Для каждой камеры КПУ создаётся сущность «Камера» с entity_id вида
`camera.<адрес>_kamera`. ffmpeg не нужен — интеграция отдаёт MJPEG-поток
камеры как есть.

### 1. Быстрая проверка (без Lovelace)

- Боковая панель **Медиа** → раздел **Камеры** → выберите нужный КПУ.
- Либо: **Настройки → Устройства и службы → ЕГДС → устройство → Камера** —
  клик по сущности открывает диалог с живым видео.

### 2. Карточка с живым видео

UI: **Изменить панель → Добавить карточку → «Изображение сущности»
(Picture Entity)** → выберите свою камеру `camera.…`.

```yaml
type: picture-entity
entity: camera.ul_tveretskaya_kamera   # подставьте свой entity_id
camera_view: live
show_name: true
show_state: false
```

### 3. Видео + кнопка «Открыть» одной карточкой

```yaml
type: vertical-stack
cards:
  - type: picture-entity
    entity: camera.ul_tveretskaya_kamera
    camera_view: live
    show_state: false
  - type: button
    name: Открыть шлагбаум
    icon: mdi:boom-gate-arrow-up-outline
    entity: button.ul_tveretskaya_otkryt
    tap_action:
      action: toggle
```

### 4. Что важно знать

- Поток включается по запросу: пока никто не смотрит, интеграция не
  держит соединение с камерой; при закрытии карточки поток закрывается.
- Трансляция на ТВ (`camera.play_stream`, Chromecast) не поддерживается —
  сущность камеры не объявляет признак `STREAM`.
- Если у КПУ нет камеры, сущность камеры не создаётся.
- **TLS-сертификаты камер** не проверяются (хост камеры — IP с
  самоподписанным сертификатом, как и в приложении). Строгую проверку
  можно вернуть параметром «Проверять TLS-сертификаты камер» в настройках
  интеграции — на API-сервер ЕГДС это не влияет.

### 5. Если окно камеры пустое

1. Откройте **Настройки → Система → Журнал** и найдите записи
   `custom_components.egds` — с версии 1.0.6 интеграция пишет причину
   прямо в журнал (WARNING, не чаще раза в 5 минут): HTTP-статус,
   SSL-ошибка, таймаут или отказ соединения — с URL камеры.
2. **HTTP 401 от камеры** — сервер ЕГДС ротонирует учётные данные камер
   (Login/Password), и устаревший пароль камера отвергает. С версии 1.0.8
   интеграция справляется с этим сама: перед каждым кадром берёт свежую
   карточку камеры из последнего опроса, а при 401 перечитывает адреса
   у сервера и повторяет запрос с новыми учётными данными. Если 401
   остаётся и после этого — в атрибутах сущности проверьте
   **`credentials_present`**: если `false`, сервер перестал присылать
   учётные данные этой камеры (сравните с приложением; если в приложении
   видео есть, а атрибут `false` — обновите интеграцию и откройте issue).
3. Проверьте доступность камеры из сети HA: в атрибутах сущности камеры
   есть **`camera_url`** (с версии 1.0.7) — откройте его в браузере на
   машине с Home Assistant. Браузер спросит логин/пароль (Basic) — это
   камерная пара из приложения ЕГДС. Если страница не открывается
   вообще — камера недоступна из вашей сети, и интеграция тут бессильна.
4. Сверьте, что в приложении ЕГДС видео с этого КПУ открывается:
   интеграция использует те же адреса и ту же Basic-авторизацию камеры.

## Как это устроено

- `api.py` — клиент: OAuth2-гранты, Bearer-запросы к `/mobile1`,
  разбор адресов, парсинг MJPEG по JPEG-маркерам (FFD8FF…FFD9).
- `coordinator.py` — опрос раз в `scan_interval`, кулдаун команд.
- `config_flow.py` — SMS-вход и reauth.
- `camera.py` — прокси MJPEG: кадры сервера заворачиваются в
  `multipart/x-mixed-replace` и отдаются в браузер.
- Ключи шифрования хранилища приложения (`Secret#1` как client_secret и
  константа тестового режима `ACE33955…`) используются только так, как их
  использует само приложение (заголовок Basic у /oauth/token).

## Ограничения

- Состояние шлагбаума сервер не отдаёт — оно «предполагаемое» (как в
  приложении).
- Закрытия протокол не предусматривает (только открытие).
- `token_expires`/`base_token` используются по назначению: access_token
  обновляется проактивно за 2 минуты до истечения (и при 401), повторный
  SMS-вход — только при недействительном refresh-токене (reauth).
- Интеграция для личного использования на собственном аккаунте.
